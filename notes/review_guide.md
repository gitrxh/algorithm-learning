# 遗忘记录与复习指南

[返回笔记索引](README.md) · [返回首页](../README.md)

这套表用于记录“哪里想不起来，以及下一次怎样检验”。它是手动维护的个人学习流程，复习间隔可以按自己的时间与难度调整。

## 四个入口

| 内容 | 遗忘表 | 编号前缀 |
| --- | --- | --- |
| 具体题目的思路、边界、复杂度 | [LeetCode](../leetcode_hot100/forgetting_log.md) | `LC-` |
| LLM 公式、shape、算法对应的 PyTorch 操作 | [LLM 算法](../llm_algorithms/forgetting_log.md) | `LLM-` |
| 可复用套路或模板的使用条件 | [模板](../templates/forgetting_log.md) | `TPL-` |
| 跨主题的语法细节与共性错误 | [学习笔记](forgetting_log.md) | `NOTE-` |

例如 GQA 的 K/V 投影维度放在 LLM 表；Python 浅拷贝导致多行列表一起改变，可以放在笔记表。按最直接的学习对象归属，同一问题只维护一处。

## 每列怎么填

| 字段 | 填写方式 |
| --- | --- |
| 编号 | 固定标识，如 `LLM-001`；以后可在笔记中引用 |
| 对象 / 链接 | 指向题目或算法笔记，方便回查 |
| 发现日期 | 第一次发现这个具体卡点的日期 |
| 具体遗忘点 | 描述能自测的问题，如“GQA 的 K/V 投影维度如何计算？” |
| 纠正要点 | 写一句能纠正错误的提示，如“K/V 输出维度为 H_kv × d，d = D / H_q” |
| 复习历史 | 每次追加 `YYYY-MM-DD：0/1/2`，可附一句结果；多次记录用 `<br>` 换行 |
| 下次复习 | 填一个明确日期；每天先看本列，优先复习到期与逾期条目 |
| 状态 | 使用 `待复习 / 巩固中 / 已掌握` |

只写“不会 GQA”太宽泛；投影维度、分组对应关系、缓存容量可以拆成不同条目。尚未学过的内容留在学习索引，不提前记作“遗忘”。

## 怎么评分

先隐藏答案、纠正要点和旧代码，再在网页重做、手推 shape 或口述原理。

| 分数 | 判定 | 后续动作 |
| --- | --- | --- |
| 0 | 想不起来或做错 | 写清错误，状态改为待复习，次日再试 |
| 1 | 看提示后才能完成 | 补上缺失的关键步骤，状态改为待复习，次日再试 |
| 2 | 独立完成，而且能解释理由与边界 | 状态改为巩固中，逐步拉长间隔 |

## 手动复习节奏

可以先采用 `1 → 3 → 7 → 14 → 30 天` 的间隔。这里的数字表示距**上一次复习**的天数，不是距首次学习的累计天数，也不是固定的记忆规律。

1. 新增遗忘条目并纠正后，先安排次日复习。
2. 评分为 2，下一次间隔依次改为 3、7、14、30 天；达到 30 天间隔后仍能独立完成，可标记“已掌握”，下次日期填 `—`，后续自行抽查。
3. 任一次评分为 0 或 1，重新从次日复习开始，保留此前历史。
4. 逾期后按实际完成日期重新安排，不补写未发生的复习；已掌握条目再次遗忘时，也更新原行并重启节奏。

## 每次只做三件事

先找“下次复习”不晚于今天的条目；闭卷尝试并评分；追加历史并改好下一次日期。实际练习情况决定学习状态，不以笔记是否齐全或是否读过作为掌握依据。
